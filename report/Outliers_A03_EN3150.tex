\begin{abstract}
Deploying deep convolutional neural networks on resource-constrained embedded microcontrollers and edge sensor nodes requires balancing classification accuracy, parameter counts, memory footprint, and computational complexity (multiply-accumulate operations). In this investigation, we explore edge-tailored vision architectures on the 9-class RealWaste dataset downscaled to $64\times 64$ spatial resolution. We evaluate a baseline CNN (\textbf{Model A}, 102,313 parameters), a custom depthwise-separable CNN constrained under 100,000 parameters (\textbf{Model B}, 22,297 parameters), and two fine-tuned state-of-the-art mobile architectures (\textbf{MobileNetV2} and \textbf{ShuffleNetV2}). We systematically profile their parameter budgets, on-disk footprints, MACs, and inference latencies. Our empirical findings demonstrate that Model B achieves a $78.2\%$ reduction in parameters and an $85.0\%$ reduction in MACs over Model A while achieving superior classification performance ($69.85\%$ vs $67.32\%$), presenting an optimal compromise for strict sub-megabyte microcontroller deployments.
\end{abstract}

\section{Introduction \& Data Preparation}

\subsection{Application Context and Problem Formulation}
Modern Internet of Things (IoT) and edge computing applications increasingly demand local machine learning inference directly on low-power sensor nodes. In municipal solid waste management, automated recycling sorting bins and conveyor-belt sorting systems require real-time material identification (e.g., distinguishing recyclable plastics and metals from compostable organic matter). Transmitting high-resolution video streams from hundreds of dispersed public bins to a centralized cloud server introduces unacceptable network latency, severe bandwidth congestion, privacy concerns, and reliance on continuous wireless connectivity. Consequently, image classification must execute entirely on-device using inexpensive embedded microcontrollers (e.g., STM32, ESP32-S3) or edge nodes (e.g., Raspberry Pi).

\subsection{Edge Sensor Emulation: Downscaling to \texorpdfstring{$64\times 64$}{64x64}}
In typical cloud-based computer vision pipelines, images are processed at $224\times 224$ or $512\times 512$ resolutions. However, on embedded edge hardware:
\begin{enumerate}
    \item \textbf{Framebuffer and SRAM Constraints:} A single uncompressed RGB frame at standard $224\times 224$ resolution requires $224 \times 224 \times 3 = 150{,}528\text{ bytes} \approx 147\text{ KB}$ of raw image buffer space. In contrast, downscaling to $64\times 64$ reduces the raw buffer requirement to $64 \times 64 \times 3 = 12{,}288\text{ bytes} \approx 12\text{ KB}$---a \textbf{$91.8\%$ memory saving}. In embedded systems with only 256 KB to 512 KB of internal SRAM (e.g., STM32H7, ESP32-S3), saving 135 KB allows the frame buffer and network activations to reside entirely in on-chip SRAM without spilling to slow external PSRAM.
    \item \textbf{Sensor Compatibility:} Low-cost CMOS camera modules commonly paired with microcontrollers (such as the Omnivision OV7670 or OV2640) operate under severe DMA FIFO limits, where downscaled windowing maximizes capture frame rates while minimizing power dissipation.
    \item \textbf{Early Layer Compute Complexity:} The computational complexity of the initial convolutional layer scales quadratically with spatial dimension ($O(H \times W)$). Reducing input spatial dimensions from $224\times 224$ to $64\times 64$ cuts the multiply-accumulate operations of the stem layer by $(224/64)^2 = 12.25\times$.
\end{enumerate}

\subsection{Deterministic Data Splitting Pipeline}
To ensure rigorous reproducibility across all team experiments, the dataset was processed with a fixed random seed ($\texttt{seed}=42$):
\begin{enumerate}
    \item Images were resized with bilinear interpolation and center-cropped to $64\times 64$ pixels.
    \item Pixel values were normalized to standard ImageNet channel statistics: mean $\mu = [0.485, 0.456, 0.406]$ and standard deviation $\sigma = [0.229, 0.224, 0.225]$.
    \item Data was deterministically partitioned into $70\%$ training (3,326 images), $15\%$ validation (713 images), and $15\%$ held-out testing (713 images).
\end{enumerate}

\subsection{Model A: Baseline Standard 2D CNN}
Model A serves as our unconstrained reference baseline. It follows a traditional convolutional architecture with 3 hierarchical feature extraction stages:
\begin{itemize}
    \item \textbf{Stage 1:} Conv2d($3 \rightarrow 32$, $3\times 3$, padding=1) + BatchNorm2d + ReLU + MaxPool2d($2\times 2$).
    \item \textbf{Stage 2:} Conv2d($32 \rightarrow 64$, $3\times 3$, padding=1) + BatchNorm2d + ReLU + MaxPool2d($2\times 2$).
    \item \textbf{Stage 3:} Conv2d($64 \rightarrow 128$, $3\times 3$, padding=1) + BatchNorm2d + ReLU + MaxPool2d($2\times 2$).
    \item \textbf{Classification Head:} Global Average Pooling (GAP), projecting to a 128-dimensional vector, followed by Linear($128 \rightarrow 64$) + ReLU, and a final Linear($64 \rightarrow 9$) classification layer.
\end{itemize}

\subsection{Model B: Lightweight Depthwise Separable CNN (Sub-100k Parameters)}
To satisfy the strict assignment constraint of keeping total parameters below $100,000$, Model B utilizes Depthwise Separable Convolutions (Howard et al., 2017). Each separable convolution block decouples spatial filtering from cross-channel feature combination:
\begin{itemize}
    \item \textbf{Depthwise Convolution:} Applies a per-channel $3\times 3$ spatial kernel ($\text{groups} = C_{\text{in}}$).
    \item \textbf{Pointwise Convolution:} Applies a $1\times 1$ convolution combining channel features from $C_{\text{in}}$ to $C_{\text{out}}$.
\end{itemize}
The stem is a single $3\times 3$ standard convolution ($3 \rightarrow 24$ channels, stride 1, padding 1), followed by three depthwise separable blocks widening the representation $24 \rightarrow 48 \rightarrow 96 \rightarrow 128$, each with Batch Normalization and $\text{ReLU6}$ non-linearities. The first three downsampling stages use $2\times 2$ max-pooling; the final block is followed by Global Average Pooling, $\text{Dropout}(0.2)$, and a single linear head producing 9 logits.

Every convolution feeding directly into a Batch Normalization layer uses $\texttt{bias}=\texttt{False}$: the BatchNorm shift parameter $\beta$ makes an immediately preceding convolution bias mathematically redundant, so omitting it saves parameters at no cost to accuracy.

\textbf{Parameter Derivation.} For a block mapping $C_{\text{in}} \rightarrow C_{\text{out}}$ with a $k \times k$ kernel, a standard convolution costs $C_{\text{in}} C_{\text{out}} k^2$ weights, whereas the separable factorization costs only $C_{\text{in}}k^2$ (depthwise) $+\; C_{\text{in}}C_{\text{out}}$ (pointwise). For block 2 ($48 \rightarrow 96$) this is $48\cdot 96\cdot 9 = 41{,}472$ versus $48\cdot 9 + 48\cdot 96 = 4{,}896$---an $8.5\times$ reduction in that block alone. Layer-by-layer:

\textbf{Exact Parameter Count:} Model B contains precisely \textbf{22,297 trainable parameters}---only $22.3\%$ of the allowed $100,000$ budget, leaving a $4.6\times$ safety margin.

\textbf{Hardware-Aware Activation Choice.} Model B uses $\text{ReLU6}(x) = \min(\max(0,x),6)$ rather than Sigmoid, Tanh, GELU or Swish:
\begin{enumerate}
    \item \textbf{Avoidance of Transcendental Computations:} Activations like Sigmoid ($\frac{1}{1+e^{-x}}$), GELU ($x\Phi(x)$), and Swish ($x\cdot\sigma(\beta x)$) require evaluating transcendental exponential functions ($e^x$). Edge microcontrollers (e.g., ARM Cortex-M4/M7) lack dedicated hardware math co-processors for transcendentals, forcing the compiler to emulate $e^x$ via expensive multi-cycle Taylor series expansions or lookup tables. Conversely, $\text{ReLU6}$ requires only simple register clamping instructions ($\texttt{CMP}$, $\texttt{BGT}$), which execute in a single clock cycle.
    \item \textbf{Suitability for INT8 Integer Quantization:} By strictly bounding the activation range to $[0, 6]$, $\text{ReLU6}$ fixes the dynamic range of activations. When performing post-training quantization to 8-bit signed/unsigned integers (\texttt{INT8}), a bounded range prevents outliers from inflating the quantization step size $S = \frac{q_{\max} - q_{\min}}{2^b - 1}$. This guarantees minimal quantization noise and prevents precision degradation on fixed-point DSPs.
\end{enumerate}

\section{Optimizer Ablation Study}
% ============================================================================
\textbf{Selected optimizer.} We train Model B with \textbf{Adam at a learning rate of $10^{-3}$}. Adam maintains per-parameter adaptive step sizes from running estimates of the gradient's first and second moments, which suits this network: a depthwise separable stack mixes layer types with very different gradient scales---depthwise kernels carry only 9 weights per channel while pointwise layers carry thousands---and a single global step size serves them poorly. The value $10^{-3}$ is Adam's standard default and was retained after the ablation below confirmed stable convergence without divergence.

To isolate the optimizer's contribution, Model B was trained three times for 20 epochs from an \emph{identical seeded initialization} (seed 42), varying only the optimizer. No learning-rate schedule was applied in any configuration, so the comparison reflects the optimizers themselves rather than an annealing policy.

\textbf{Results.} Adam dominates on every measure, crossing $50\%$ validation accuracy by epoch 2 and finishing at $71.81\%$. Standard SGD at the same budget never reaches $50\%$, plateauing at $47.69\%$ with a minimum validation loss of $1.493$---nearly double Adam's $0.785$.

\textbf{Impact of the momentum parameter.} The cleanest evidence sits in the two SGD rows, which differ \emph{only} in $\mu$. Introducing $\mu = 0.9$ lifts final validation accuracy from $47.69\%$ to $63.53\%$, a gain of $15.84$ percentage points, and converts a configuration that never reaches $50\%$ into one that does so by epoch 7. Momentum accumulates an exponentially weighted velocity over past gradients:
\begin{equation}
v_t = \mu v_{t-1} + \nabla_\theta \mathcal{L}(\theta_t), \qquad \theta_{t+1} = \theta_t - \eta\, v_t,
\end{equation}
so that at $\mu = 0.9$ a persistent gradient direction is amplified by up to $1/(1-\mu) = 10\times$ relative to plain SGD, while oscillating components in high-curvature directions partially cancel between consecutive steps. The practical effect is twofold: the optimizer traverses the shallow, elongated regions of the loss surface far faster, and the damping of perpendicular oscillation permits progress that plain SGD achieves only by raising $\eta$---which in this compact parameter space destabilizes training. Momentum therefore recovers most, though not all, of the gap to Adam at identical cost per step, confirming that the deficit of plain SGD here is one of optimization dynamics rather than model capacity.

\subsection{Architectural Superiority of Depthwise Separable Convolutions}
Model B is not merely competitive but \emph{superior} to Model A on every single classification metric while using $78.2\%$ fewer parameters and $85.0\%$ fewer MACs, which is the central empirical insight of this study. Two factors explain this:
\begin{enumerate}
    \item \textbf{Implicit Regularization against Overfitting:} At $64\times 64$ spatial resolution with only 3,326 training images, Model A's 102k parameters afford excessive capacity that causes early memorization. The depthwise separable factorization restricts cross-channel connections, acting as a strong structural regularizer that generalizes better on the test set.
    \item \textbf{Resolving Visual Ambiguities:} As observed in Figure~\ref{fig:custom_cms}, Model B classifies 48 of 75 \textit{Miscellaneous Trash} instances correctly against Model A's 10. The broad channel mixing of pointwise convolutions allows better feature recombination for visually heterogeneous materials.
\end{enumerate}

\textbf{Compute Cost vs. Wall-Clock Latency.} Although Model B eliminates $85.0\%$ of multiply-accumulate operations, its training time per epoch (11.24 s) is comparable to Model A's (11.02 s), and its single-image inference latency improves by $15.7\%$ (3.97 ms vs 4.71 ms). This highlights a well-known edge computing reality: at small batch sizes and low resolutions, wall-clock time is governed by memory access cost (MACost), kernel launch overhead, and cache thrashing rather than peak ALU throughput. Depthwise convolutions have low arithmetic intensity (FLOPs per byte of memory read), meaning memory bus bandwidth becomes the operational bottleneck.

\section{SOTA Transfer Learning}
% ============================================================================

\subsection{MobileNetV2 and ShuffleNetV2 Architectures}
To benchmark our custom sub-100k models against established mobile computer vision backbones, we fine-tuned two lightweight State-of-the-Art (SOTA) architectures:
\begin{enumerate}
    \item \textbf{MobileNetV2 (Sandler et al., 2018):} Utilizes inverted residual blocks with linear bottlenecks. The block first expands the channel dimension by an expansion factor ($t=6$) using $1\times 1$ convolutions, applies a $3\times 3$ depthwise convolution with ReLU6, and projects back to a lower-dimensional manifold using a linear $1\times 1$ pointwise convolution without activation (preventing non-linear destruction of low-dimensional manifold information).
    \item \textbf{ShuffleNetV2 (Ma et al., 2018):} Designed strictly around hardware-aware memory access cost (MAC) guidelines. At the beginning of each unit, feature channels are split into two branches ($1 - c$ and $c$). One branch remains an identity path, while the other undergoes three successive convolutions with equal input/output channels. The branches are concatenated and subjected to a channel shuffle operation to enable cross-group information exchange across subsequent stages.
\end{enumerate}

\subsection{Transfer Fine-Tuning Protocol}
Both networks were initialized with ImageNet-1k pretrained weights. Their terminal 1000-class linear classification heads were replaced with a Linear($D \rightarrow 9$) head adapted for RealWaste. Fine-tuning was executed for 20 epochs using the Adam optimizer ($\text{lr}=10^{-3}$, weight decay $10^{-4}$), a Cosine Annealing learning rate schedule ($T_{\max}=20$), batch size 32, and Cross-Entropy loss under the exact same $70/15/15$ split.

As shown in Table~\ref{tab:sota_results} and Figure~\ref{fig:sota_cm}, transfer learning yields a massive jump in test accuracy ($\approx 88.6\%$ vs $69.85\%$ for Model B):
\begin{itemize}

\end{itemize}

\subsection{Microcontroller Feasibility (Bare-Metal Deployments)}
In ultra-low-power edge vision nodes (e.g., smart trash cans powered by solar cells or coin batteries running on an ARM Cortex-M4/M7 microcontroller such as the STM32H7 or ESP32-S3):
\begin{enumerate}
    \item \textbf{Storage and Memory Limits:} Microcontrollers typically possess only $256\text{ KB} - 1\text{ MB}$ of internal SRAM and $1\text{ MB} - 2\text{ MB}$ of internal NOR Flash.
    \item \textbf{Infeasibility of SOTA Models:} Pretrained SOTA models require $4.98\text{ MB} - 8.76\text{ MB}$ of read-only weight storage, exceeding internal microcontroller Flash. Furthermore, their intermediate activation buffers require several megabytes of working RAM, mandating external SPI PSRAM. External memory interfaces incur high latency cycles, introduce PCB routing complexity, increase Bill of Materials (BOM) cost by $\$1.50-\$3.00$ per unit, and increase power draw by $300\%-500\%$.
    \item \textbf{Model B Featherweight Advantage:} Model B requires only \textbf{98 KB of Flash storage} and approximately \textbf{64 KB of SRAM} for activations. It executes entirely from zero-wait-state internal tightly coupled memory (TCM), dissipating minimal energy per inference.
\end{enumerate}

\subsection{Quantization and Integer Arithmetic Suitability}
Model B is tailored for 8-bit integer post-training quantization (\texttt{INT8}):
\begin{equation}
    q = \text{round}\left(\frac{r}{S}\right) + Z, \qquad S = \frac{r_{\max} - r_{\min}}{q_{\max} - q_{\min}}
\end{equation}
By utilizing $\text{ReLU6}$ non-linearities, the maximum activation value is clamped to $r_{\max} \le 6.0$, eliminating extreme outlier values that compress quantization grids. Quantizing Model B from \texttt{FP32} to \texttt{INT8}:
\begin{itemize}
    \item Shrinks the serialized model weight footprint from $98\text{ KB}$ down to \textbf{$\approx 25\text{ KB}$}.
    \item Enables 4-way parallel SIMD operations on 32-bit registers ($\texttt{SADD8}$, $\texttt{SMUL8}$) on ARM Cortex-M DSP extensions (CMSIS-NN).
    \item Eliminates floating-point emulation overhead entirely.
\end{itemize}

\subsection{Final Synthesis Recommendation}
For battery-operated, standalone IoT sensor nodes deployed in municipal sorting bins under strict cost ($<\$5$) and power ($<100\text{ mW}$) envelopes, \textbf{Model B} provides the ideal trade-off: it satisfies all sub-100k budget limits, fits on-chip, and delivers solid $69.85\%$ classification accuracy. For edge gateway hubs or robotic conveyor sorters connected to mains power (e.g., Raspberry Pi 4 or Nvidia Jetson Nano), \textbf{ShuffleNetV2} represents the superior design choice, delivering $88.64\%$ accuracy with optimal memory access efficiency.
